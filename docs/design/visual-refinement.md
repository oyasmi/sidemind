# SideMind 视觉与交互优化方案

建议方向：温和中性色、克制的橙色点缀、清楚的设置层级。精致感主要来自阅读节奏、控件一致性和恰到好处的反馈。

本文记录最初的设计方案；用户确认后的插件实现与验证结果记录在文末。用浏览器直接打开 [preview.html](preview.html)，可切换配置/对话界面、五个设置栏目、浅色/深色/系统主题、字体和字号，并查看服务商表单布局。视觉稿不读写插件数据、不发起 API 请求。视觉稿用中文便于评审，正式落地建议沿用当前产品语言，本地化另行考虑。

## 1. 当前问题与判断

检查范围：`assets/css/ui.css`、`assets/js/ui.js`、`options/`、`sidebar/`，以及使用现有浏览器测试夹具渲染的浅色、深色页面。示例数据包含一个服务商、两个模型和两个角色；未使用真实密钥或真实请求。

| 观察到的问题 | 对使用的影响 | 优化方向 |
| --- | --- | --- |
| 五个设置部分纵向堆叠，都用较大的外层卡片 | 1160px 宽的示例配置页约 2073px 高；外观设置位于后半段，需滚动或点锚点定位 | 保留五个栏目，按栏目显示内容，用 hash 记录位置 |
| 页头包含大标题、宣传语和说明，下面各卡片再次放标题和说明 | 真正的设置被推远，信息密度缺乏节奏 | 每个栏目只保留标题和一句任务说明 |
| 大多设置都用“标签—全宽控件—长说明”的相同结构 | 简单开关和高级参数看起来一样复杂 | 常规项采用设置行，复杂项保留纵向表单，高级项按需展开 |
| 服务商显示名称、协议、完整地址和所有模型名称的连续文本 | 服务多、模型多时难扫描 | 名称为第一层，地址/协议为第二层，模型使用克制的标签或数量摘要 |
| 服务商弹窗有多段协议解释与技术说明 | 在 800px 高视口中，模型区域靠近底部，部分操作需内部滚动 | 基础连接与模型分组；缩短常驻说明，技术细节按需展开 |
| 输入框聚焦时，同时出现强调色边框和外侧描边 | 两圈橙色很抢眼，界面显得紧张 | 统一鼠标与键盘焦点规则，避免双重强描边 |
| 浅色对话使用纯白背景；深色沿用偏冷灰底色和较亮的桃橙强调色 | 长文阅读的底色、气泡、强调色之间缺少统一调性 | 两套主题分别调亮度与饱和度，以暖中性灰为基础 |
| `--accent` 同时服务于按钮、链接、焦点、代码关键词；按钮文字取自 `--bg-secondary` | 改一个颜色容易牵动多个组件，品牌色与内容颜色混在一起 | 拆分动作、品牌、内容和状态语义 |
| 侧栏顶部长标题和三个按钮并排，下面再放全宽模型下拉框 | 窄侧栏中标题易截断，固定区域稍重 | 保留两层结构，模型入口降为轻量控件，长名称给完整信息入口 |
| 透明的消息操作行仍占据高度；底部完成状态长期显示 | 用户问题与回复间距偏松，固定区域持续重复提示 | 分别调整消息间距；完成状态短暂显示，长期保留异常和未完成状态 |

现有自动保存、外观预览、主题首屏缓存、草稿保留、撤销、流式阅读位置、原生 dialog、键盘支持和减少动效支持都有价值，应在改版时保留。此轮的重点是让这些能力更容易理解和使用。

## 2. 推荐视觉基调

### 配色

保留 SideMind 橙色图标，界面内使用更沉稳的陶土橙。浅色采用暖灰画布和近白表面；深色采用略带中性色倾向的炭灰，避免大片纯黑与高亮橙色相邻。下面是视觉稿的起始值，正式落地仍需在实际内容上校准。

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 页面底色 | `#F5F4F0` | `#1C1F1D` |
| 卡片、阅读表面 | `#FDFCF9` | `#232724` |
| 用户气泡、轻量填充 | `#EEEDE8` | `#2C312C` |
| 正文 | `#292C29` | `#E1E5DC` |
| 次要文字 | `#62675F` | `#B3BBAD` |
| 辅助文字 | `#70766C` | `#98A18F` |
| 装饰分隔线 | `#E3E3DA` | `#353C33` |
| 控件边界 | `#8D9585` | `#697461` |
| 品牌/选中强调 | `#A14C2C` | `#E4AF8F` |
| 主操作填充 | `#A14C2C` | `#D6A685` |
| 主操作文字 | `#FFFAF6` | `#271E17` |

用相对亮度公式计算，以上正文/表面组合对比度约为 13.77:1、11.85:1；次要文字约为 5.65:1、7.66:1；主按钮文字约为 5.65:1、7.52:1。控件边界与表面对比度约为 3.02:1、3.08:1。装饰线允许更轻，不能用装饰线单独承担输入框的辨认任务。这些计算只覆盖列出的颜色组合，不能代替完整页面的可访问性检查。

主题变量建议增加 `--action-primary`、`--on-action`、`--surface-input`、`--surface-code`、`--border-control`、`--text-link` 和独立的代码高亮变量。颜色仍集中定义在共享 CSS，不在页面内散落具体色值。

### 字体、间距与形状

- 界面使用系统字体，无外部字体。配置正文 13–14px，栏目标题 24–26px，分组标题 15px，辅助文字 12px。
- 对话正文默认维持 14px 和约 1.75 行高，保留现有 13–16px 字号设置；正文偏好与界面控件字号分开，避免放大文字后工具栏跟着拥挤。
- 间距围绕 4/8/12/16/24/32px 形成节奏。设置行约 16–20px 内边距，分组之间约 24px，关联信息保持靠近。
- 控件圆角 8px、分组 12px、弹窗 14–16px，减少不必要的胶囊形状。阴影主要用于浮层，常规分组依靠底色和细分隔线。
- 界面图标统一到一套轻量线性风格，16–18px 图形、32–36px 点击区。采用自托管 SVG；按实际使用范围逐步替换现有图标，避免在包里长期保留两套完整资源。

## 3. 配置页：优先投入

### 五个栏目，单个内容区

保留“服务与模型 / 助手角色 / 对话偏好 / 外观 / 数据与关于”，左侧导航约 172–184px，右侧内容区约 760–824px。桌面整体宽度约 1080–1120px；移除占用首屏的宣传型大标题。

点击栏目只显示对应内容，支持 `#appearance` 等直接链接、刷新恢复和浏览器前进后退。避免五个栏目都切成多个二级页面。窄屏改为顶部横向导航；选中项切换后自动进入可见范围，短屏下优先给内容留空间。

视觉稿演示了栏目切换；hash、历史和恢复行为属于正式落地范围。

### 服务与模型

- 服务行采用“轻量标记 + 名称/协议 + 地址 + 模型摘要 + 编辑”的结构。服务较少时完整展示，模型多时展示前几个和“另外 N 个”。完整列表在编辑时查看。
- 一个分组内只有“添加服务”使用填充主按钮；“编辑”为次级操作。删除放进编辑弹窗底部的独立危险操作区，保留现有确认逻辑。
- “已配置”“本设备未授权”“刚刚检查成功/失败”分别表达。不能把保存了密钥或拥有主机权限标成“已连接”，也不展示未经检查的绿色成功点。
- 服务表单使用两个明确分组：连接信息、可用模型。基本输入包含名称、API 地址、密钥和协议；协议值始终可见，解释可折叠。地址旁显示低强调的完整请求路径。
- 密钥显隐、连接检查和模型建议保留。检查结果在检查按钮附近显示；失败保留输入，给出下一步。协议/地址/密钥发生变化时清除过期结果。
- 模型显示名称与模型 ID 使用持续可见的字段标签，placeholder 只给示例。模型 ID 使用等宽字体。小屏变为每模型两行。
- 弹窗头尾固定、内容内部滚动。保存时按钮显示进度；验证错误放到字段旁，网络/保存错误放到操作附近。不要仅靠页面角落的临时通知。

### 对话偏好与角色

- 流式回复是二元设置，改为带明确标签的原生 checkbox 开关；一句话说明，不常驻 SSE 等实现细节。
- 高级参数保持折叠。每项先说明对用户有什么影响，API 字段和兼容性说明按需展开。模型默认/不发送参数的现有语义保持一致。
- 不因视觉改版改变已有温度、输出上限和推理参数的默认值，不静默覆盖不适用的设置。
- 角色显示名称、内置标记和最多两行摘要；编辑时查看全文，避免一段很长的指令改变整个列表节奏。

### 外观

- 主题放在第一项，以“浅色 / 深色 / 跟随系统”三个可键盘选择的选项呈现；选中状态同时有描边和填充。
- 右侧预览采用与正式对话共享的颜色、字体和内容样式。包含用户消息、正文和输入区；正式落地补入短代码块，验证代码与主题的协调性。
- 字号用“默认 · 14px”等有实际意义的名称；字体与字号变化立即反映到预览。主题同时作用于配置页与对话页。
- 自定义字体保留，作为字体选项的条件输入。常规用户不需要看到额外的空文本框。

### 保存与数据

保留当前“偏好自动保存、弹窗明确保存”的规则：页头依次显示“正在保存 / 已保存 / 保存失败·重试”。初次打开未产生改动时显示“更改自动保存”，不要误报刚完成保存。保存成功回到安静状态，失败持续保留且不只靠颜色区分。

导入/导出和隐私说明维持现有边界。API 密钥默认不导出，导入前预览保留；本轮无需新增数据管理仪表盘。

## 4. 对话页：阅读与输入优先

- 保留上方标题与操作、下方模型选择的结构。模型选择从全宽强边框控件改为轻量入口，可先调整原生 select 外观；需要分组和搜索时再增加自定义选择器。长名称有省略和完整名称提示。
- 标题和工具按钮保持稳定位置。不要把必要操作全部藏进新菜单，也不要把标题区域挤成只能显示几个字。
- 用户问题使用低饱和气泡，助手正文直接排在阅读表面。消息之间约 24–28px；单独收紧用户消息与首条回复之间由隐藏操作行造成的空白。
- 普通回复减少重复头像装饰；模型信息降为安静的辅助层。切换模型的历史分隔继续保留，仍能辨认每条回复由谁生成。
- 复制、重试等沿用现有行为：最新回复可见，历史回复在 hover 或键盘聚焦时显示，触屏保持可见。动作出现不引起正文跳动。
- 输入区使用与阅读表面接近的底色、清晰边界和单一焦点反馈。默认占高约 96–112px，继续自动增长；字号与边距在 320px 宽度下仍能容纳角色和发送按钮。
- “已完成”短暂出现后收起，计时和 token 留在回复尾部。等待、生成中、停止、连接错误、输出截断和完成未确认等有意义的状态继续清楚显示。
- “查看最新回复”、撤销和保存错误使用明确的层级与固定锚点，避免互相覆盖。错误持续显示直到用户处理；不能和短暂成功反馈使用同样的消失策略。
- 思考过程保持默认折叠；代码块采用独立表面、低强调工具栏和独立语法色，保留复制/展开和横向滚动；表格只在内容区横向滚动。
- 空对话提供一句直接引导和最多三个轻量建议。未配置服务时只突出连接服务这一项行动。

## 5. 精致交互的共同规则

1. 点击区域充足，视觉可以轻；按钮都具有名称，不能只靠图标形状解释操作。
2. 鼠标聚焦用边界/弱光晕，键盘聚焦用一圈清晰描边；避免两圈同等强度的强调色同时出现。
3. 悬停、选中、禁用、加载和错误各有明确规则，选中与成功不混用。
4. 动效集中在 120–160ms 的颜色和透明度变化；关闭减少动效时不动画。内容流式出现和展开时以稳定布局为先。
5. 保留 Esc、焦点返回、IME 输入和快捷键的现有约束。界面变漂亮不应改变用户已经形成的操作习惯。

## 6. 落地顺序与验收

| 顺序 | 工作 | 涉及文件 |
| --- | --- | --- |
| P0 | 共享颜色语义、排版、边框、焦点、按钮状态；分别校准两套主题 | `assets/css/ui.css`，必要时调整 `assets/js/ui.js` |
| P1 | 配置页栏目导航、设置行、外观预览、服务/角色摘要、弹窗信息密度 | `options/options.html`、`options/options.css`、`options/options.js` |
| P2 | 对话头部、消息节奏、输入区、完成反馈、代码/推理层次 | `sidebar/sidebar.html`、`sidebar/sidebar.css`、少量 `sidebar/sidebar.js` |
| P3 | 主题/状态/尺寸回归，清理重复样式和不再使用的图标资源 | 现有浏览器测试和打包流程 |

验收用真实长度的中英文、长服务名/模型名、多角色、Markdown 表格与代码，不仅看空状态：

- 侧栏在 320/380/480px 下无整页横向溢出；配置页在 520/840/1160px 下布局合理；短屏弹窗的取消和保存始终可达。
- 浅色、深色、跟随系统分别检查；包括系统主题运行中变化、打开时无闪白、设置在已打开的另一页面同步。
- 检查文本/背景和焦点/控件边界对比度，辅助文字保持可读；暗色禁用按钮不呈现为亮色主操作。
- 键盘完整走通栏目、主题选项、开关、dialog 和错误重试。放大阅读字号到 16px 后工具栏保持稳定。
- 完整覆盖保存中/失败/恢复、未授权、检查失败、首次使用、流式等待/停止/失败/未完成等状态。
- 复用现有 Node 与 Playwright 检查，对新增导航与状态行为增加必要断言；单纯间距/配色不增加镜像实现的测试。
- 不引入框架、UI 组件库、在线字体、CDN 或新的构建流程。方案文档与视觉稿位于 `docs/`，现有 `build.sh` 的目录白名单不会把它们打进扩展包。

## 8. 实现与验证（2026-10-21）

已落地共享主题、按栏目显示的配置页、主题单选项、流式开关、模型标签和字段标签、删除操作移入编辑弹窗、轻量模型选择、独立阅读字号/字体、消息间距和完成反馈。连接检查使用修订标识，编辑地址、密钥、协议或关闭弹窗后，旧检查结果不会重新显示。删除失败在弹窗内持续显示，保留配置和编辑状态。

图标统一使用本地 SVG sprite，删除了 750,413 字节的旧字体图标文件和样式；保留零运行依赖、原生控件和原有存储/API 适配方式。侧栏临时通知改为输入区上方的内联反馈，避免盖住发送按钮。版本号保持 `1.4.0`。
